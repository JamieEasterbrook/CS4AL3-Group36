\section{Introduction} % DONE

Our challenge is to construct a model that will predict immediate short-term weather patterns around Toronto, given a large sample of past weather information. There has been a lot of recent development with AI-based weather models, and there is no shortage of large, open-source weather datasets to train models with, so we figured this would be an interesting project to tackle. Because of this boom in AI weather models, many newer ones have been performing significantly better than traditional physics-based models, in both accuracy and speed \citep{rackow2024robustnessaibasedweatherforecasts}. Our approach to solving this problem is with a recurrent neural network (RNN), that can make use of the sequential structure of the data in order to leverage patterns in past weather conditions, allowing us to predict future short-term trends.

Many aspects of weather prediction are heavily time-based so we will try to capture both with our RNN. A good example of this is that when close to a large lake, we can predict that the chance of rain will increase after a period of high temperatures due to Lake-Effect precipitation \citep{LakeEffectRainEvents}. Since data-driven models can capture patterns like this without needing the background reasoning of why or how it happens, it follows that they are overtaking physics based-models with recent developments \citep{rackow2024robustnessaibasedweatherforecasts}, so we will compare our algorithm to physics-based models in order to properly judge its efficacy.

\section{Related Work} % MOSTLY DONE

One project we discovered involved generating accurate predictive data for several weather metrics \citep{HAN2021107601}. This project was a neural network-based predictive algorithm, with several iterative versions of this model. The project experimented with comparing feed-forward neural networks (FNNs) to recurrent networks, eventually implementing a gated recurrent unit to help with the vanishing gradient problem. The algorithms each took sequential weather data and compiled it into a model to predict future trends of those data points, in order to make clean, more consistent synthetic data for other models to draw on.

Another project we looked into was an RNN-based weather prediction task that would classify images based on non-exclusive weather states \citep{zhao2019cnnrnnarchitecturemultilabelweather}. They used self-annotated data, and their model would return a list of probabilities that each state was occurring. This algorithm initially was based on a single variable classifier, but the paper quickly concludes that a non-exclusive multi-class algorithm is the most efficient and accurate way to label outputs. This makes sense, as often a lot of weather conditions overlap, so reducing to just ‘wind’ or ‘rain’ is reductive, and can cause loss of information.

Finally we looked into a report comparing numerical and machine learning-based weather prediction models. The article concluded that machine learning was much faster and more efficient to run, but couldn’t handle extreme points on the data nearly as well as numerical models, resulting in harsher weather conditions being poorly handled \citep{WAQAS2025306}. This is helpful for error analysis, as it could explain poor performance on the dataset, should it arise.

\section{Dataset} % DONE

Our dataset is a large sample of public domain weather data taken from the Government of Canada’s website through a provided Bash script. The dataset consists of measurements taken roughly every 3 hours, ranging from June 11$^{th}$, 2013, to September 26$^{th}$, 2025. The exact time between measurements is highly irregular, resulting in inconsistent amounts of labels on a day-to-day basis. Additionally, the table is full of null values, and many empty or extraneous columns, including two that were completely unlabelled.

Due to the frequency and time range of recordings, our dataset has ~107,000 data points, which means we can afford to drop invalid or incomplete points.

\subsection{Labels} % DONE

The table is provided as a .csv file, with built-in labels for each point, classifying what weather conditions were currently unfolding at the given time. These labels are grouped together and treat different magnitudes of the same weather as different prefix labels, for example “Mostly Cloudy” and “Paritally Cloudy” are treated as separate cases. We want to combine these umbrella terms by adding a discrete numeric method of indicating the scale of each weather event. This will allow us to add similar such labels back into the output during postprocessing, while using the magnitude of the even in this way to potentially discover more patterns about the dataset itself.

\subsection{Preprocessing} % DONE

For our preprocessing, we removed missing or redundant values from the dataset. Since we only requested data from a station outside of Toronto’s Pearson International Airport, which means that all the location and station data columns are identical, so we can remove those. There was a large amount of mostly empty flag columns and the humidex was missing most of its values, we removed all of those features.

For the date and time information, we want to parse it manually to work with our recurrent neural network. We added in a delta time column, recording the time in hours since the last measurement, and parsed the day and month integer values into sinusoidal functions.

Lastly, we take our labels and split them into a list of each characteristic, then we group the labels into label classes, and convert the prefix labels into real valued magnitudes representing the scale of the labeled weather event. Finally we export the processed data into a separate file for later splitting into training and test sets.

\section{Features} % DONE

The features of our processed dataset include:
\begin{itemize}[nosep]
        \item Date Information (Day, Month and Year)
        \item Time (LST)
        \item Wind Speed (km/h)
        \item Wind Direction (10s of degrees)
        \item Air Pressure (kPa)
        \item Visibility (km)
        \item Relative Humidity (%)
        \item Dew Point Temperature ($^{\circ}C$)
        \item Precipitation Amount (mm)
\end{itemize}

Our input values contain all of this information, as we have filtered out any columns missing any values. These features were manually determined by human inspection of the dataset.

We engineered the date and time features to have more readable numeric values to be more compatible with our RNN. We added in a delta time column, recording the time in hours since the last measurement, and parsed the day and month integer values into sinusoidal functions.

\section{Feedback and Plans}

The TA agreed that our RNN is a viable approach to this problem and checked the implementation of the RNN model. The overall correctness of the code was confirmed, and it was also advised that, a smaller, more efficient model like random forests could be used for explorative purposes. A multi-modal approach was also suggested, where we can use images from weather satellites as an additional input to our model, if possible.

We have identified these areas for improvement in the next phase of the project: model, amount of data and quality of data. We plan to try new models such as transformers, since our current RNN was running into some issues due to the sparsity of the output set. We also plan to collect larger and more reliable data from alternative sources, since we've found that the current dataset has many missing values and possible human errors.
